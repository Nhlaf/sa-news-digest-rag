# News Digest RAG Agent – Frontend Architecture

## 1. Objective

Build a **responsive web frontend** for the existing News Digest RAG Agent backend.

The frontend will provide a user-friendly interface for interacting with the backend's news ingestion and RAG capabilities.

The frontend must allow users to:

1. Check whether the backend is available.
2. Enter a natural-language news query.
3. Optionally provide a location.
4. Specify the maximum number of news items.
5. Submit the query to the backend.
6. View the generated news digest.
7. View the news articles returned by the backend.
8. View article source and publication information.
9. Open the original news article.
10. Manually trigger news ingestion.
11. View ingestion status and results.

The frontend is a **client application only**.

It must not directly access MongoDB, news websites, embeddings, LangChain, or the LLM.

## 2.1 In Scope

### Frontend

* React application
* TypeScript
* Responsive web UI
* News query interface
* Location input
* Maximum articles input
* News digest display
* News article cards
* Source links
* Backend health indicator
* News ingestion controls
* Loading states
* Error states
* Empty-result states

### Backend Integration

The frontend integrates with the existing backend through:

```text
GET  /health
POST /news/query
POST /ingest/run
```

### Configuration

The backend URL must be configurable using:

```text
VITE_API_BASE_URL
```

---

## 2.2 Out of Scope

The frontend must not implement:

* News website scraping
* Cheerio
* Playwright
* Article extraction
* Article cleaning
* Article chunking
* Embedding generation
* BM25 search
* Vector search
* MongoDB access
* LangChain RAG
* LLM calls
* API keys for AI providers
* MongoDB credentials

These responsibilities remain in the backend.

# 10. Query Request

When the user submits the form, call:

```http
POST /news/query
```

Request structure:

```json
{
  "query": "Summarise South African technology news from yesterday",
  "location": "South Africa",
  "maxItems": 8
}
```

The frontend must only send fields supported by the backend API.

The frontend must not attempt to perform retrieval itself.

# 30. Security Architecture

The browser must only know the backend API URL.

```text
Frontend
   │
   │ VITE_API_BASE_URL
   ▼
Backend
   │
   ├── LLM API keys
   ├── Embedding API keys
   ├── MongoDB credentials
   └── News source configuration
```

Never place the following in frontend code:

```text
MISTRAL_API_KEY
OPENAI_API_KEY
MONGODB_URI
MongoDB username
MongoDB password
```

The frontend must never connect directly to MongoDB Atlas.

## Core Principle

The frontend is a **thin client**.

It is responsible for:

```text
User interaction
       +
API communication
       +
Presentation
```

The existing backend is responsible for:

```text
News ingestion
       +
Article processing
       +
Embeddings
       +
MongoDB Atlas
       +
Hybrid retrieval
       +
RAG
       +
LLM generation
```

The frontend must integrate with the backend through its existing REST API rather than reimplementing any backend functionality.
